# 公众号草稿箱发布

把 Markdown 文章直接送进微信公众号草稿箱，排版自动套用（正文 16px / 段后距 24px / 行高 1.75 / 字间距 1px，标题 16px 蓝色加粗，引用 15px，代码块灰底等宽保留换行）。

## 触发场景

- 用户说「发布到草稿箱」「把这篇发到公众号」「推送公众号」「生成公众号草稿」等
- 用户要求把某篇 Markdown 稿件转成公众号草稿

## 前置条件（不满足先说明，不要尝试调用）

1. 公众号已认证；微信开发者平台（developers.weixin.qq.com/platform）→ 我的业务和服务 → 选择公众号 → 接口管理 → 接口权限与额度 → 服务端接口 → 草稿管理，已开通
2. 密钥可用：环境变量 `WECHAT_APPID` / `WECHAT_SECRET`，或运行脚本时当前目录（或脚本上级目录）存在 `.env` 文件
3. 本机公网 IP 已在微信开发者平台「基础信息 → IP白名单」中（出口 IP 会轮换，40164 报错时提示用户重加）

## 执行步骤

1. 确认要发布的 md 文件（用户未指定时先询问）
2. 先预览，不直接推送：

   ```bash
   python3 scripts/wechat_draft.py --file <文件> --dry-run
   ```

3. 检查预览输出：
   - 有【截图/配图/图片】占位但找不到文件时，把缺失清单列给用户，等用户补图后再正式发布，不要用 `--force` 硬推
   - 排版参数可让用户按需覆盖：`--font-size` / `--line-height` / `--letter-spacing` / `--para-margin`
4. 用户确认后正式发布：

   ```bash
   python3 scripts/wechat_draft.py --file <文件>
   ```

5. 输出草稿 media_id，提醒用户到公众号草稿箱预览，人工确认后再点发布

## 硬规则

- 默认只进草稿箱，**绝不自动群发**；只有用户明确要求且二次确认后才加 `--publish`
- 不读取、不打印 `.env` 里的密钥内容，不把密钥写进任何文件
- 封面文件（`cover-wechat.png` / `cover.png`）只作缩略图，不放进正文
- 图片占位缺文件时中止，不用 `--force` 硬推（除非用户明确要求）
- 发布前必须 dry-run 预览一遍

## 常见报错

- `40164`：IP 不在白名单 → 提示用户去微信开发者平台「基础信息 → IP白名单」重加（运营商 NAT 的出口 IP 会轮换）
- `48001`：接口未授权 → 公众号未认证，或「接口管理 → 接口权限与额度 → 服务端接口 → 草稿管理」未开通
- `40001` / `40125`：AppSecret 错误或已重置 → 重新生成并更新 .env
- 找不到封面图 → assets 里放 `cover-wechat.png` / `cover.png`，或用 `--cover` 指定
